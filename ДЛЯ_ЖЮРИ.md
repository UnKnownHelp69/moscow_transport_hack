# Инструкция для жюри

Два ROS 2 Humble пакета:
- `tram_odometry` - решение (Python, `ament_python`);
- `tram_vehicle_msgs` - сообщения `VelocitySensor` и `DriverControllerCommand`.

Внешний интернет при сборке не нужен. Зависимости - только стандартные пакеты Humble: `rclpy`,
`nav_msgs`, `sensor_msgs`, `geometry_msgs`, `diagnostic_msgs`, `python3-numpy`.
Данные модели (маршруты, станции, модель тяги, масштабы колёс) лежат внутри пакета.

## 0. Всё одной командой

`WS` ниже - корень workspace чекера организаторов (`check-code`): в их Docker-контейнере это
`/workspace` (так задано в их `Dockerfile` и `scripts/run.sh`), без Docker - путь к папке
`check-code`. Положите bag в `$WS/bags/` (каждый bag - своя папка с `metadata.yaml` и `.db3`) и
выполните:

```bash
WS=/workspace                                   # или путь к check-code
cd $WS/src && git clone https://github.com/UnKnownHelp69/moscow_transport_hack.git mos_trap
cd $WS && src/mos_trap/scripts/run_jury.sh bags  # второй аргумент - темп, по умолчанию 1
```

Скрипт:
1. подключает наш пакет сообщений `tram_vehicle_msgs` (пакет из основного датасета, с типом
   `DriverControllerCommand`, как разрешили организаторы) и исключает из сборки пакет чекера;
2. собирает workspace (`colcon build`);
3. прогоняет через чекер все bag из папки по очереди: для каждого - наш узел, `metrics` чекера и
   `ros2 bag play`;
4. печатает таблицу: RMSE и максимум ошибки положения, RMSE скорости по каждому bag и среднее.
   Логи каждого bag - в `checker_out/<bag>/`, таблица - в `checker_out/summary.txt`.

Проигрывание идёт в реальном времени: bag чекера длится ~22 мин, с темпом 2 - ~11 мин.
Разделы ниже - то же самое по шагам.

## 1. Сборка

### 1.1. В workspace чекера организаторов (`check-code`)

```bash
cd $WS/src                                       # WS - как в §0
git clone https://github.com/UnKnownHelp69/moscow_transport_hack.git mos_trap
# итог: $WS/src/{checker_ros, tram_vehicle_msgs, mos_trap}
touch tram_vehicle_msgs/COLCON_IGNORE            # пакет сообщений чекера не собираем
rm mos_trap/tram_vehicle_msgs/COLCON_IGNORE      # собираем наш, из датасета
cd $WS && source /opt/ros/humble/setup.bash
colcon build && source install/setup.bash
```

Узел использует позицию контроллера водителя (`/vehicle/driver_position_cmd`, тип
`DriverControllerCommand`). В нашем пакете сообщений он есть, `VelocitySensor` в нём тот же, что
у чекера. Два пакета с одним именем ломают `colcon build` («Duplicate package names»), поэтому
один из них исключается файлом `COLCON_IGNORE`.

### 1.2. Отдельно (без чекера)

```bash
mkdir -p ~/ws/src && cd ~/ws/src
git clone https://github.com/UnKnownHelp69/moscow_transport_hack.git mos_trap
rm mos_trap/tram_vehicle_msgs/COLCON_IGNORE      # других tram_vehicle_msgs нет - собираем наш
cd ~/ws && source /opt/ros/humble/setup.bash && colcon build && source install/setup.bash
```

## 2. Запуск

**С чекером организаторов** одной командой. Скрипт запускает узел и `metrics` чекера,
проигрывает bag и печатает итоговые метрики:

```bash
cd $WS
src/mos_trap/scripts/run_with_checker.sh bags/30618_88aea4d9        # [rate] [vehicle_id]
```

**Набор bag одной командой.** Скрипт прогоняет через чекер все bag из папки по очереди и
собирает таблицу. Логи каждого bag - в `checker_out/<bag>/`, таблица - в
`checker_out/summary.txt`:

```bash
cd $WS
src/mos_trap/scripts/run_all_bags.sh bags 2          # папка с bag, темп (по умолчанию 1)
```

Пример на тестовом bag чекера (`bags/30618_88aea4d9`, темп 2, наш пакет сообщений):

```
bag                      pos_rmse_m    pos_max_m  vel_rmse_ms
30618_88aea4d9             1.158305    11.100372     0.048768
mean (1 bags)                 1.158       11.100        0.049
```

`pos_rmse_m` и `pos_max_m` - RMSE и максимум 3D-ошибки положения, `vel_rmse_ms` - RMSE
скорости, это строки `distance` и `velocity` из итога чекера. В строке `mean` RMSE
усредняются по bag, максимум - наибольший. Между прогонами одного bag RMSE положения
колеблется в пределах 1.1-1.2 м: время доставки сообщений в ROS каждый раз немного другое.
С `gnss_correction:=false` (GNSS только для выставки) - 1.5-1.7 м.

**Вручную:**

```bash
# терминал 1: решение (eval:=true - наш монитор точности по GNSS, на оценку не влияет)
source /opt/ros/humble/setup.bash && source install/setup.bash
ros2 launch tram_odometry tram_odometry.launch.py vehicle_id:=30618
# терминал 2
source /opt/ros/humble/setup.bash && source install/setup.bash
ros2 bag play <путь>/30618_xxxxxxxx          # любой темп, например --rate 5
```

`source install/setup.bash` нужен в **каждом** новом терминале. Без него `ros2 bag play` не
найдёт тип `tram_vehicle_msgs` и молча пропустит топики тележек (в выводе будет
`Ignoring a topic ... package 'tram_vehicle_msgs' not found`), а узел ничего не получит.

- `vehicle_id` - префикс имени bag (`30618` или `30639`), по нему выбирается масштаб колёс.
  Без него масштаб 1.0: для 30618 разница пренебрежима, для 30639 это +0.27 % к пути.
- Узел можно запускать и без launch-файла:
  `ros2 run tram_odometry tram_odometry_node --ros-args --params-file $(ros2 pkg prefix tram_odometry)/share/tram_odometry/config/params.yaml`.
- Узел ждёт первый валидный GNSS-фикс, поэтому его лучше запускать до bag. Если узел запущен
  позже, он выставится по первому фиксу, который получит: в bag чекера GNSS приходит редко, но
  всю запись.
- Несколько bag подряд можно проигрывать в один запущенный узел: по скачку времени входов
  узел понимает, что начался новый bag (в логе `input time jumped ...: new bag, estimator
  reset`), сбрасывает оценку и заново выставляется по GNSS.
- Проигрывание идёт в реальном времени: bag чекера длится ~22 мин, с `--rate 2` - ~11 мин.

## 3. Входы и выходы

| топик | тип | содержимое |
|---|---|---|
| вход `/vehicle/front_bogie_velocity`, `/vehicle/rear_bogie_velocity` | `tram_vehicle_msgs/VelocitySensor` | скорость тележки, км/ч |
| вход `/vehicle/driver_position_cmd` | `tram_vehicle_msgs/DriverControllerCommand` | позиция контроллера (тяга/торможение) |
| вход `/sensing/gnss/{master,rover}/fix` | `sensor_msgs/NavSatFix` | выставка по первым 3 с после первого валидного фикса; если фиксы приходят и дальше - мягкая поправка положения (`gnss_correction`) |
| **выход `/result/velocity`** | `tram_vehicle_msgs/VelocitySensor` | продольная скорость, **м/с** |
| **выход `/result/position`** | `nav_msgs/Odometry` | `pose.pose.position`: `base_link` в MGRS 37U local (`x = UTM37N_E − 300000`, `y = UTM37N_N − 6100000`, `z` - уровень головки рельса); ориентация - курс пути; `twist.linear.x` - скорость; ковариации заполнены |
| выход `/result/diagnostics` | `diagnostic_msgs/DiagnosticArray` | 1 Гц: выставка, `s`, `σ_s`, проскальзывание, отвергнутые показания, коррекции по станциям, частота, задержка |

- Штамп выхода равен `header.stamp` входного сообщения, которое его породило.
  `frame_id`: `map` у положения, `base_link` у скорости; `child_frame_id = base_link`.
- Публикация идёт на каждое входное сообщение: ~40 Гц (контроллер 20 Гц + тележки 2×10 Гц).
- До первого валидного GNSS-фикса выхода нет. После выставки в логе появляется
  `alignment done (...); GNSS kept for gentle corrections`. С `gnss_correction:=false` подписки
  на GNSS закрываются (`GNSS subscriptions closed`).
- QoS подписок best-effort (совместим с reliable/transient-local издателями), публикация reliable.

## 4. Логи, метрики, задержка

- **Лог ноды** (1 Гц): `out N Hz, latency mean X / max Y ms, s=…, sigma=…, corr=…, slip=…`.
  Задержка - от начала обработки входа до публикации.
- `ros2 topic hz /result/position` - частота; `ros2 topic echo /result/diagnostics` - диагностика.
  Обе команды запускайте в третьем терминале (тоже после `source install/setup.bash`), **пока
  идёт** `ros2 bag play`: после конца bag узел ничего не публикует, и команды просто ждут.
  Ожидаемо: `average rate` около 40 при `--rate 1`. Если в логе узла есть
  `running on wheel speeds only`, собран пакет сообщений без `DriverControllerCommand`:
  узел работает только по колёсам, пересоберите по §1.1.
- **Чекер организаторов** печатает `Velocity metrics` / `Position metrics` (RMSE и максимум).
- **Наш монитор** `tram_odometry_eval` запускается с `eval:=true` или через
  `scripts/demo_play_bag.sh <bag>`. Эталоном служит GNSS `base_link` из двух антенн по tf.
  Каждые 10 с монитор печатает RMSE, в конце - строку `FINAL …`.
