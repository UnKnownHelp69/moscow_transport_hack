# mos_trap: резервная одометрия беспилотного трамвая

Решение кейса «Резервная одометрия по модели» хакатона Московского транспорта. Пакет ROS 2
Humble оценивает скорость и положение трамвая **без IMU**, по скоростям двух тележек и позиции
контроллера водителя. GNSS нужен для начальной выставки; если фиксы приходят и по ходу рейса,
они мягко поправляют положение вдоль пути (организаторы это разрешили). Скорость от GNSS не
зависит никогда.

**Главное: решение работает без GNSS.** После выставки по первым секундам GNSS положение и
скорость считаются только по колёсам, контроллеру и карте. На независимом bag чекера так
получается RMSE 1.5-1.7 м, медиана мгновенной ошибки 0.5 м, 0.8 м за первые 20 минут. Дрейф в
конце рейса - 0.012 % пути (медиана val), около 0.6 м на рейс длиной ~5 км. GNSS по ходу рейса, если он
есть, только мягко уточняет результат.

**Результаты:**

| проверка | RMSE положения 3D: GNSS только для выставки | с GNSS по ходу рейса | RMSE скорости |
|---|---|---|---|
| чекер `check-code`, bag `30618_88aea4d9` (не входил в калибровку), ROS 2 | 1.5-1.7 м | **1.1-1.2 м** | **0.049 м/с** |
| 30 отложенных рейсов (val, ~160 км), среднее / медиана / худший | 1.64 / 1.27 / 4.15 м | 1.50 / 1.19 / 4.08 м (пачки GNSS раз в 2 мин) | 0.046 м/с |
| 30 рейсов калибровки (train), среднее / медиана | 1.32 / 0.90 м | 1.13 / 0.77 м (пачки) | 0.061 м/с |

- Без GNSS в пути медиана дрейфа в конце рейса - 0.012 % пути.
- Выход 40 Гц, задержка 0.34 мс (максимум 12.5 мс), CPU 3.4 % одного ядра, память 99 МБ.
- Модель откалибрована только по train; val использовался для выбора вариантов модели.

Сборка в workspace `check-code` и прогон bag - в [`ДЛЯ_ЖЮРИ.md`](%D0%94%D0%9B%D0%AF_%D0%96%D0%AE%D0%A0%D0%98.md) §2-3.

## Структура репозитория

```
tram_odometry/           ROS 2-пакет решения
  tram_odometry/         estimator.py (ядро без ROS), node.py, eval_node.py, route.py, geo.py
  tram_odometry/data/    калибровка: маршруты, станции-маяки, модель тяги, масштабы колёс
  config/params.yaml     все параметры; launch/; test/ (юнит-тесты ядра)
tram_vehicle_msgs/       сообщения (VelocitySensor, DriverControllerCommand)
analysis/                сборка модели (build_model.py), оценка (evaluate.py), сбои (robustness.py)
dataset/map/             официальные центрлинии пути (MGRS 37U) и архив OSM; bag-файлы не в git
docs/                    модель, допущения и параметры, метрики, ограничения и план развития, график
ДЛЯ_ЖЮРИ.md              инструкция по проверке
scripts/                 run_with_checker.sh, run_all_bags.sh, demo_play_bag.sh, fetch_data.sh
```

bag-файлы для офлайн-оценки загружает `scripts/fetch_data.sh` из ветки `data`
в `dataset/data/` (или задайте путь через `MOS_TRAP_DATA=/path`).
